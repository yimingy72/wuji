# Closed core lifecycle

For a new clone and W1 profile setup, follow [local development](../../../docs/local-development.md). W1 additionally uses the `wuji-web-assessment-lab:w1` image and `closed-web-assessment-v1` profile; the default fixture commands below preserve the original core path. Current migration head is 0008. No private run files or historical PVC contents are distributed with Git.

Use the existing test run generated by normal platform lifecycle. No edits to its source SHA:

    scripts/platform/core.sh prepare --run-file /absolute/run.json --model-profile-version-id UUID --image wuji-core:core-loop
    scripts/platform/core.sh up --run-file /absolute/run.json
    scripts/platform/core.sh status --run-file /absolute/run.json
    scripts/platform/core.sh down --run-file /absolute/run.json

Prepare requires an already built core image plus the existing worker images with actual Docker RepoDigests. It reads existing gateway metadata and management key, never salt or gateway DB credentials. It enables only the pre-created execution role, rejecting privilege escalation/memberships, and retains generated credentials in an immutable run-specific Secret. Private core-<run_id>.json contains config/identity/UIDs but no credential values. Interrupted preparation reuses the original Secret. Existing core configuration cannot silently change model version.

Up creates four single-instance Deployments and three Services using one frozen core image. Only control receives namespace-scoped Pod/ConfigMap/Secret/PVC RBAC; no pods/exec, RBAC modification, or cluster privileges. Only control and Dispatcher hold Core credentials. Artifact and Cairn data use separate run-specific PVCs. Cairn uses native HOME-derived SQLite configuration and native fifteen-second settings. A Bearer ASGI wrapper surrounds the original app without changing Core protocol/schema. Dispatcher uses native YAML and the managed backend.

Port 18502 is registered in the existing process ledger with normal ownership/start markers. Only wuji-test and the owning worktree/current SHA are accepted. Resource writes and deletes check owner/run labels and remembered UID; delete uses UID/resourceVersion preconditions. Down removes this run's core Deployments/Services/ConfigMap/RBAC and forwarding process, preserving PVCs and Secrets. Existing API, gateway, PostgreSQL and port 4180 are untouched. Task runtime Pods remain the controller's responsibility; stop/reconcile tasks before taking the control service down.

Build separately from repository root: `sh scripts/platform/build-core.sh` after `./scripts/uv.sh sync --frozen --group task-runtime --group cairn-bridge`. The wrapper supplies the verified pinned Cairn Git cache as a BuildKit named context; a plain Docker build without that context is insufficient. The image uses project Python 3.13.15, uv 0.12.11 from toolchain/manifest.json, and frozen uv.lock with task-runtime/cairn-bridge groups. All workspace manifests and source packages are present. Deployment commands select control, native Cairn wrapper, Dispatcher or synthetic fixture. No model request or deployment is performed during static generation.
