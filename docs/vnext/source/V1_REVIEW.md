# Wuji 草案审查与修订说明

版本：1.0-review；日期：2026-09-12。对象：[原始 422 行草案](INPUT_SPEC.md)。目标文档：[SPEC](SPEC.md) 与 [PLAN](PLAN.md)。本次不是产品代码安全审计或测试报告。

## 结论

原草案不是方向错误：三层决策、持久 WorkItem、单写 Session、迟到结果核对、账本与观测分离等值得保留。但它仍是“保留旧后端的过渡架构”，且在事实语义、完成竞态、受控拓扑、状态机和协议细节上不足以直接作为完整重构合同。

本轮用户明确了新的目标：新系统不依赖 Cairn，使用 MAF 和 `TopologyFlowCanvas`。修订以此为高优先级需求，不把原文中“保留 legacy 可执行路径”继续作为终态。

优先级含义：P0 是在新系统接受任务/发布前必须解决的合同问题；P1 是实现阶段必须收口的可靠性与维护问题；P2 是范围、可用性或验收表达问题。这些是**草案风险**，不是已复现的产品漏洞。

## 三、关键语义修正示例

### 不把模型输出“升级”为真正 Fact

Agent 写：“记录 A 存在缺陷。”——保存 Claim，不是 Fact。

可信读取工具在固定文档摘要/版本下返回字段 `status=ready`——可由抽取器保存 Fact“在该次读取的记录中，status 字段为 ready”。

工具文本写：“系统安全。”——最多证明“工具返回了这段文本”；不能直接形成“系统安全”的 Fact。进一步命题需要适用规则/人审和支持证据。

### 不把 React Flow 当数据库

`TopologyFlowCanvas` 的 `nodes`、`edges` 和坐标是业务投影与布局。业务对象改变必须经过领域命令。拖线不能新建“支持某结论”的证据关系，删除节点不能删除归档证据。

### 不把 complete 当固定第四个 Agent

初始化由普通代码完成；Reason/Explore 是可分配工作类型；校验既可以是确定性程序，也可以让另一个 Agent 提交复核意见，但后者仍不是事实权威。CompletionReview 是业务评审记录，不要求固定存在 Complete Agent。

## 四、这次没有得出的结论

不能据草案或静态源码断言 MAF 比 Pi 更聪明、压缩效果更好、取消完全可靠或迁移工作量很小。不能认定用户本地不存在 `TopologyFlowCanvas`。不能认定旧事实都可升级成可信证据，也不能保证模型网关并发计费零超支。

## 五、使用修订稿

SPEC 保留原稿的 Task、Origin、GoalContract、Observation、Claim、Intent、WorkItem、AgentRun、Session、Verification 和 CompletionReview 等术语，并明确新增 FactLedger、GraphProjection 与完成收敛协议。PLAN 只针对新架构，不要求先给 Cairn 接 MAF；已有独立工具/身份/主题可以经审核复用，旧执行内核不进入新交付物。
