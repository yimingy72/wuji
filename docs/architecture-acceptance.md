## 1. 测试环境与证据

只使用自建 HTTP/DNS/模型模拟服务、测试租户和隔离 Kubernetes 测试环境。故障注入只作用于平台测试实例和测试数据，不访问第三方目标、不在真实目标建立持久化、不改变其业务数据。

每次验收记录平台提交版本、镜像 digest、Schema/策略版本、CNI/Kubernetes/模型适配器版本、配置和观测时间。证据包括 API 结果、ToolCall/attempt/预算账本、目标模拟服务请求计数、出口日志、进程状态和资源清理结果；测试凭据也需脱敏。

表中的“通过条件”均是未来实现的要求。不得仅凭日志声称拒绝，应同时用测试服务计数或网络观测确认未到达目标。故障及并发测试需要重复执行，记录实测结果，不以单次成功替代统计。

阶段表示预计交付顺序；若某能力提前启用，其对应验收也必须提前完成。没有 CLI/Browser 时，使用专用测试进程验证运行隔离与停止机制；真实 Adapter 上线前补做对应场景。Phase 1 的事件隔离通过事件查询 API 验证，SSE 在 Phase 2 接入时增加持续订阅验证。

## 2. Phase 1：受控工具闭环

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| S01 | 合法授权、合法目标、允许端点的一次 HTTP 观察 | 仅产生预期目标请求；策略版本、调用、证据和审计能关联 |
| S02 | 过期/撤销授权、未知 origin、业务有副作用的端点 | 派发或出口拒绝，模拟目标对应请求数为零；HTTP GET 不自动获得豁免 |
| S03 | URL 输入中的路径与编码变体、IPv6/IP 字面量及不一致 Host | 按规范化 Schema 处理 URL 输入；授权边界按当前 Scope 字段判断，不把路径段当作独立 ACL，也不能通过另一种 origin 表示绕过范围 |
| S04 | 测试重定向链、测试 DNS 地址切换、同 IP 的不同 Host | 每次实际连接绑定验证过的目标；越界目的地无请求；跨 origin 不携带凭据 |
| S05 | Runtime 尝试直连测试集群服务、元数据模拟服务、其他 Task、任意 DNS | CNI/出口阻断；不发送到真实元数据服务；IPv4/IPv6 都覆盖 |
| S06 | 工具容器请求本地 MCP、读取控制凭据卷、伪造租户/Task/attempt、越过逐调用出口许可 | 无凭据读取权限，无有效调用权限；同 Pod/localhost 和 Task 网络可达不豁免认证 |
| S07 | 工具名合法但注入未知参数、shell 语法、插件路径或路径逃逸 | 严格 Schema/Adapter 拒绝；不启动任意程序、不越出授权工作目录 |
| S08 | 超出请求总量、速率、并发、响应大小、进程和临时存储配额 | 执行端限制生效；重定向/重试计数；同目标多任务服从聚合上限 |
| S09 | 正在运行时取消，包括后台测试进程和已建立连接 | 提交后不再授权新调用；在途许可在停止窗口内失效；进程终止有证据，确认前保持 cancelling |
| S10 | Runtime 与控制面失联、出口控制连接失联 | 最后有效续约后在配置上限内停止执行和转发；初始目标 35 秒，记录实测值 |
| S11 | 暂停、超过 drain deadline、再恢复 | paused 时无活动请求；超时调用已停止；恢复重新检查授权、预算和策略 |
| S12 | Pod 创建后 DB 回写失败、Controller 多副本同时协调 | 能按 task/attempt/UID 收敛；同时最多一个获准执行的 attempt |
| S13 | 旧 Pod 失联后重建、延迟到达的旧续约/执行许可 | 先隔离旧出口再激活新 attempt；旧 epoch 消息不能恢复执行 |
| S14 | 清理失败、孤儿 Pod/Service/Secret/卷/出口授权 | 明确 cleanup_pending；重试可完成；不删除不属于本平台的资源 |
| S15 | 租户 A 请求 B 的任务、证据、事件，后台连接池切换租户 | API/DB/对象访问均拒绝；无上下文残留；对象键和事件游标不构成授权 |
| S16 | Runtime 请求 privileged/hostPath/ServiceAccount Token 等禁止配置 | 准入拒绝；工具不兼容时不自动放宽 RuntimeProfile |

## 3. Phase 2：单 Agent 与恢复

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| A01 | 网页/工具结果含有“修改 Scope、泄漏凭据、访问其他目标”等指令 | 外部文本留在数据通道；任何越权工具请求被执行层拒绝 |
| A02 | 数据只允许私有模型，首选模型不可用或能力不满足 | 仅在允许候选中 fallback；无候选则失败，外部模型模拟服务未收到数据 |
| A03 | Gateway、适配层和客户端均出现超时 | 同一逻辑调用可查询状态；只有 Gateway 决策新尝试，无隐式重试倍增 |
| A04 | 多模型请求并发预占、fallback、结果不明、取消后返回用量 | 总预占不超预算；所有尝试入账；未知结果不提前释放额度 |
| A05 | 请求已到模拟目标、结果落库前 Runtime/Router 崩溃 | 调用进入 unknown/reconciling；不会在无法核实时盲目再发请求 |
| A06 | 相同 tool_call_id 重投，以及同 ID 携带不同参数 | 相同请求返回已有状态/结果；不同参数拒绝；去重不依赖 MCP session ID |
| A07 | LangGraph 检查点与业务账本一方提交后另一方失败 | 恢复按稳定调用 ID 对账；不会把已有目标操作当作未执行 |
| A08 | DB 事务成功但事件发布失败、重复和乱序消息、SSE 重连 | Outbox 可补发；消费者去重/校验版本；终态不回退，补发仍鉴权 |
| A09 | 对完成任务执行审计回放 | 目标和模型模拟服务新增请求数均为零；新验证需要独立执行许可 |
| A10 | 策略变更与派发/暂停/取消并发 | 拒绝旧版本新派发；排空或停止受影响调用后切换；授权不能被缓存绕过 |
| A11 | Graph/Prompt/工具 Schema 升级后恢复旧检查点 | 使用兼容版本或明确暂停迁移，不用新逻辑静默重放旧操作 |

| ID | 场景 | 通过条件 |

| M01 | Dispatcher 并发认领同一 Intent，过期 Worker 延迟回写 | 只有有效 owner 推进任务；fencing token 阻止旧写入 |

## 6. 评估、知识与交付模型新增场景

原有 S/A/M/P 场景与 D01–D20、F01–F12、H01–H10 共组成 80 个后续场景。各阶段只执行已实现且与本次变化有关的最小集合；已有证据按实际候选复用，未覆盖项继续保留。阶段控制功能开放时机，不能豁免已经适用的安全边界。

| ID | 最早阶段 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| D01 | Phase 2 | 场景包含未授权目标、缺失身份或未安装 Adapter | 模板不能扩大 Scope；缺失项显示 blocked/not_run；不能声称完整场景已执行 |
| D02 | Phase 2 | Skill/角色发布新版本、撤销已绑定版本，资料伪装 SKILL.md | 普通更新不改变 ConfigSnapshot；撤销停止新派发；非平台知识不升级为指令，加载只在 manifest/权限内 |
| D03 | Phase 2 | 跨项目 Reference ID、旧资料链接和相同内容摘要命中共享缓存 | 读取与缓存均校验归属和版本；摘要不跨数据策略泄露内容；恢复读取原快照 |
| D04 | Phase 2 | Worker 成功退出但未满足验证前提，或一般观察主张获得 confirmed | 不自动确认漏洞；执行、verdict、Finding 三者分开；有可核对主张与原始证据 |
| D05 | Phase 2 | 凭据缺失、DNS/环境阻断、响应截断、证据冲突、方法完整但未复现 | 前四类不能标记 not_reproduced；仅完整执行且观察充分的结果形成有条件负结论 |
| D06 | Phase 2 | 12 项示例计划及动态新增/排除、重复验证同一项 | 2 excluded、6 evaluated 时显示 6/10；不删未完成项抬高比例；版本变更可追溯，多次验证不重复计数 |
| D07 | Phase 2 | 无下一步 Intent、预算耗尽、尚有业务不确定结论或 ToolCall unknown | 保存 outcome/stop_reason；业务 partial 可披露后交付，未知执行仍须核对，不能伪造 criteria_met |
| D08 | Phase 2 | 零 Finding 的评估任务结束 | 报告包含 Scope、方法、覆盖快照、负结果、限制和未完成项；不输出无依据的“目标安全” |
| D09 | Phase 3 | VerificationRun 交接，旧 Worker 延迟提交、完成事件重复或丢失 | fencing 阻止旧写入；从执行账本恢复结果，不因通知丢失重新打目标；用量能追到实际 Worker |
| D10 | Phase 3 | Verifier 只有 Explorer 总结、原始证据无权访问，或规则要求独立复核 | 不以模型同意代替证据校验；同主体不能冒充职责分离；额外目标访问仍须新许可 |
| D11 | Phase 2 | 多域名共用 IP、应用协议/端口不同、历史 DNS 过期、发现范围外资产 | 保留资产身份和关系来源，不误合并；过期关系不授权当前连接，发现不扩 Scope |
| D12 | Phase 2 | HTTP、协议、代码观察与反证，选择 evidence 标记，部分正文被截断 | 保持类型化 payload；反证与完整执行审计不因展示筛选丢失；证据链可回溯，截断不冒充完整 |
| D13 | Phase 2 | 报告捕获后 Finding/覆盖状态变化、渲染失败重试、证据到期删除 | 重试读取固定 manifest；旧 commit 内容不漂移；缺失证据显示原因，不静默引用最新文件 |
| D14 | Phase 2 | 已冻结正文渲染、Markdown 导出、历史回放及重新验证 | 前三项新增目标/模型请求为零；首次正文生成如用模型须在冻结前授权并保存结果；重新验证建立新受控 Run/Task |
| D15 | Phase 2 | 多模型别名/Key 共享 QuotaGroup，fallback、未知尝试与缓存计费 | 共享配额不倍增；预算和容量都通过才调用；未知尝试不立即释放全部容量，缓存口径不重复计数 |
| D16 | Phase 4 | 人工确认 Finding、报告修复、执行模板、撤回发布和修复复测 | 研判/证据/修复/发布/模板状态独立；改为 fix_reported 不自动 resolved；复测不隐式重开旧 Task |
| D17 | Phase 4 | 同一漏洞多次发现、改标题、历史报告基线与当前身份/范围不同 | 按主张及归属去重，Revision 不增加漏洞数；不同条件无法比较时标记未知，未测不算已修复 |
| D18 | Phase 4 | Git/压缩包资料携带 hook、子模块、外联依赖、解压越界和凭据 | 限定来源与 commit；解析离线受限；不默认运行代码或递归外联，超配额拒绝且来源凭据不泄露 |
| D19 | Phase 4 | 发布者权限不足、多个格式导出、未实现机器格式、并发 publish | 无权限不发布；导出绑定同一 commit 和生成器版本；格式校验有证据，未实现格式不广告支持 |
| D20 | Phase 4 | 资产关系每跳权限、工作区证据筛选、复用历史证据和越界图查询 | 全链路项目隔离、遍历配额生效；历史来源/时间保留；源证据不可访问时明确缺失，不通过图或缓存泄露 |

## 7. 前端与接口协作新增场景

F01–F12 验证界面与平台契约一致。前端 Mock 用于交互与异常夹具测试，不能替代后端鉴权、目标请求计数、执行停止和清理证据。P01/P02 中涉及首版会话撤销、下载鉴权和证据预览的边界，应随 F04/F05/F08 提前验收；SSE 在 Phase 2 按 F07 补充。

| ID | 最早阶段 | 场景 | 通过条件 |
| --- | --- | --- | --- |
| F01 | Phase 1 | 固定工具链构建、契约生成、必需状态字段或 Schema 版本不兼容 | 冻结依赖安装、类型检查和构建有记录；生成物与源契约一致；不兼容输入明确报错，不显示成功/空结果 |
| F02 | Phase 1 | 范围预览后输入变化、Scope 更新、授权到期、创建重复提交 | 服务端重新校验并拒绝过期/不一致预览；相同幂等键不重复创建，不能静默采用更宽范围 |
| F03 | Phase 1 | 取消返回 202、提交超时、重复点击、unknown 调用及清理失败 | 提交中/取消中/已取消/结果核对/清理待完成可区分；超时核对原命令，不换键盲发；停止结论有执行证据 |
| F04 | Phase 1 | 项目切换、注销、权限失效后旧查询迟到及缓存命中 | 旧请求与上下文不回填新页面；清理私有缓存/表单/预览；无跨项目数据；API 后续读取和旧下载链接独立鉴权 |
| F05 | Phase 1 | 会话过期、伪造写请求、仅手改菜单/按钮权限、失效登录回跳 | 服务端鉴权和 CSRF 校验拒绝；API 错误不被当作 SPA 页面；不泄露会话/Provider 凭据，回跳不能跳往任意站点 |
| F06 | Phase 2 | 快照交接期间发生事件、重复/乱序事件、慢查询回写、游标过期 | 交接无事件遗漏；按事件 ID/资源版本处理；任务终态不回退；无法补发时重新同步，不重发目标操作 |
| F07 | Phase 2 | SSE 断线重连、权限撤销、多 Tab 切换和迟到事件 | 页面组件复用订阅并释放旧连接；重连核验权限，不叠加重连循环；实测撤销窗口，旧项目事件不回填 |
| F08 | Phase 1 | Markdown/HTML/SVG 证据含脚本、危险链接、外联图片或伪造类型 | 控制台同源无目标脚本执行；不自动外联；敏感下载独立鉴权；大文件和不支持类型走受控降级路径 |
| F09 | Phase 2 | blocked、not_run、not_reproduced、Finding 各维度状态、零发现 | 页面状态不混同；覆盖按服务端计划版本展示分子/分母；不完整验证不计通过；零发现保留限制说明 |
| F10 | Phase 2 | 查看旧 ReportCommit、导出 Markdown、证据过期、从终态重新验证 | 固定版本不漂移；缺失证据显示原因；查看/导出不产生目标或模型请求；复测创建重新授权的关联新任务 |
| F11 | Phase 1 | 生产静态部署、深链接刷新、升级旧页面、API/文件错误和缓存 | 页面可恢复；API/文件不落入 SPA fallback；运行配置无密钥；私有数据无共享缓存；Phase 2 追加 SSE 代理验证 |
| F12 | Phase 1 | 键盘完成主路径、窄窗口、10,000 条任务夹具、长时间日志刷新 | 焦点和错误可识别、颜色非唯一状态提示；服务端分页/有界日志生效；记录体积、耗时、内存及已确定阈值的实测结果 |

## 8. Harness 与上下文集成新增场景

H01–H10 在 Phase 2 单 Agent 开放前验证。优先使用可控模型模拟服务验证故障边界，再在允许的数据策略与预算内用真实网关验证协议组合；记录实际 Harness、客户端、checkpointer 版本。已完成的 ping 和空参数工具调用不能算作这些场景通过。

| ID | 场景 | 通过条件 |
| --- | --- | --- |
| H01 | 长历史、多条证据、大工具结果触发框架压缩/卸载 | 实际使用框架机制；压缩后可按证据 ID 查回来源；摘要不改变 Scope、事实可信度或原证据；窗口配置有依据 |
| H02 | 压缩、工具选择或自动评估使用辅助模型；预算耗尽及压缩失败 | 每次请求包含 Task/AgentRun 与 purpose，均经 Gateway 预占/结算；取消后不发起新请求；失败次数有界 |
| H03 | 分别触发用户补充指令、框架 interrupt、平台暂停、取消和恢复 | 不启动第二个主循环；只有执行排空/出口冻结才 paused；停止有平台证据；旧 epoch 不能 resume，迟到结果不触发工具 |
| H04 | Harness 默认工具、工作记忆写入、平台工具、自动插件与子代理 | 真实工具表符合注册分类；仅允许隔离工作区内记忆写入；目标访问走 Router；无宿主目录/任意网络；派生 Worker 不绕过 Dispatcher |
| H05 | 模型动作已保存、工具已执行但框架检查点未提交后重启 | 复用已保存 ModelCall/ToolCall，模拟服务无额外请求；新生成工具 ID 不绕过去重；合法新观察也不被按参数误去重 |
| H06 | 流式模型中断、SDK/中间件重试、工具 unknown 与模型修正非法参数 | 传输重试只有指定责任层创建新尝试；unknown 工具保持核对；合法纠错作为有限新模型回合单独计费 |
| H07 | 模型暂时不可用、跨协议 fallback、续接状态不兼容、容量未知 | 可用性与能力分开；不将不兼容会话内容直接换模型；安全边界显式迁移且不重发已执行动作；未知能力不冒充支持 |
| H08 | 跨租户 thread/store 访问、模型摘要/卸载文件/trace 导出、保留期删除后恢复 | 框架表与存储隔离单独验证；不能凭 thread ID 读取；默认无第三方 tracing；清理覆盖框架数据，缺失时明确不可恢复 |
| H09 | 高速 Token 流、业务事件、慢消费者和 SSE 重连 | Token 片段不逐片写 Outbox 或推进 Task 版本；缓冲有界；快照与最终摘要可恢复；SDK 内部事件/隐藏推理不外泄 |
| H10 | Task 运行期间 Harness/客户端/ContextPolicy 升级与旧会话恢复 | 绑定原版本或明确暂停迁移；不静默改变压缩与工具行为；Phase 1 业务状态操作由 Graph 复用，未产生第二套写入权威 |

## 9. 验收记录格式

```text
case_id / run_id / executed_at
platform_commit / image_digests / dependency_versions
harness_version / model_client_version / checkpointer_version / context_policy_version
web_build / browser_version / viewport / network_profile / api_contract_version
policy_version / config_snapshot_id / coverage_plan_version / configuration / test_fixture
expected / observed / pass_or_fail
task_id / verification_run_ids / call_ids / trace_ids / evidence_refs / report_commit_id
remaining_limits / reviewer
```

阶段门槛涉及的场景只有在对应候选上取得实际证据后才能标记完成；目录中的未来场景不构成每次改动的必跑清单。暂未实现的能力保持关闭；涉及新操作类别或信任边界的能力先更新架构与验收场景，再开放给任务。
