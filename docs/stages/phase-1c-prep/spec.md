## 1. 本阶段目标

完成“选择场景 → 填写任务 → 保存草稿 → 恢复编辑 → 创建待启动任务 → 列表/详情核对 → 取消”的真实配置闭环。先完成更新后的可点击原型评审，再接正式前后端。

## 2. 原型必须表达的产品行为

- 任务页移除“HTTP 首批闭环 / Agent 完整体验”，使用创建按钮、搜索、场景/状态筛选和列表。
- 首步先选择 CTF、Web 单点渗透、综合渗透、攻防演练、代码审计，再展示场景所需输入。
- Web 单点完整四步：场景/目标、对象/范围、运行配置、确认。域名/子域/协议端口是范围；路径只作为入口/关注点，删除路径白名单与黑名单配置。
- 默认不提供账号，不展示登录凭据输入。资料可选；后续运行中凭据成果共享仍按黑板设计。
- 运行配置展示模型方案、工具能力、DNSLog、出口/环境和预算的业务含义；未实现的能力明确为规划，不允许用户填了以后系统静默忽略。
- 其他四类在原型中展示差异：CTF 题目/附件，综合渗透资产与网络，演练单位名称及资产批准关口，代码审计上传/Git 与静态/动态阶段。全部使用合成数据，不做文件导入或网络操作。
- 创建成功先待启动；原型可模拟执行，模拟开关收进预览设置。此批不扩展流量查看器和抓包交互；保留已确认的信息结构供后续实现。
- 五套主题和现有工作台风格沿用，不再次改造视觉系统。当前 4185 原型只在拥有其进程的前提下有序更新。

## 3. 首批正式能力

正式版本先支持 Web 单点的配置与创建；场景目录可以表达全部五类的能力状态，但尚未交付的类型不得提交虚假任务。其他类型先完成原型输入规划，不一次实现所有数据导入、靶场、内网接入与代码构建。

### 3.1 配置与草稿

- 使用服务端场景目录和默认值，前端不自行判断执行能力。至少区分可创建与可执行，目录显示具体不支持原因。
- 新草稿与 Task 分开；显式保存，允许字段不完整；刷新/回访从服务端恢复。草稿只对原作者且仍有项目权限时可见、可编辑，禁止跨项目复用。
- 编辑采用版本条件更新，避免两标签页覆盖；保存成功才显示已保存，失败保留页面输入。完整性由创建预览检查，草稿不触发 DNS、模型、目标请求或隐式文件下载。
- Web 输入为任务名称/目标说明、入口、域名/子域规则、创建者确认的任务范围、预算和配置引用；名称提供默认建议。类型化输入与后续场景可扩展，不能把所有场景塞进 target_url。
- 模型、工具、环境等只选择可用且已发布的配置引用。此批规划组织级基础模型配置页面，由管理员维护；任务创建者选择已发布模型方案。其他工具/环境管理按真实能力展示，不扩展为完整配置中心；未配置项明确为空/不可用，不能伪造模型方案。草稿可保存缺失项；配置完整性和执行就绪性分别展示。

### 3.2 创建与任务状态

- 创建仍复用预览、规范化完整输入摘要、当前鉴权、CSRF/Origin 和幂等回执。重复提交不得创建多个 Task。
- 保存部分草稿不消耗预览；草稿转换为 Task 时冻结当时完整配置，之后改草稿不能影响 Task。创建请求绑定草稿版本和预览版本，冲突返回可理解的重新预览提示。
- 新任务为 ready（待启动），列表/详情读取服务端快照；正常显示场景、目标摘要、范围、预算和配置状态。不得只保存在浏览器内存。
- 本阶段 execute capability 为 false，启动按钮不可用并说明原因；API 不接受实际启动，也不建立没有消费者的执行队列。不把命令已接受冒充运行。
- ready 可以取消，继续使用命令版本与幂等核对；证据/活动调用为零，无需清理。
- Viewer 只读可见 Task；不创建或控制，不读取其他用户草稿。原提交者命令回执访问规则继续复用 B2/B3。

### 3.3 兼容与范围

- 公开契约拟从 0.4.0 更新到 0.5.0；公共 DTO、响应校验器、迁移由唯一负责人维护。准确接口和错误响应在开工前的 Plan 模式评审冻结，不让开发代理自行决定。
- 当前 queued 任务保持历史记录可查且不能被未来 Runtime 自动执行；旧命令、回执和事件不可改写成曾经 ready/start。历史未执行任务在显示上标明待处理/未启动，具体迁移需保留版本和事件因果。
- 新目标设计不含路径级权限。当前存量 Scope 有路径约束时不能简单删字段扩大授权：原记录保持，创建新域名级批准记录或明确标为不兼容。界面指出需要新授权，不能悄悄把旧范围扩大为全域。
- 通过域名正常连接其解析地址不等于授予该 IP 独立测试权。外域依赖正常加载与外域主动测试继续保留为不同概念，但本阶段不实现出网策略。

## 4. 验收标准

1. 原型可选择五类场景，Web 四步正确表达最新需求；没有旧开发阶段入口、路径权限和账号配置。
2. 正式 Web 草稿保存、刷新恢复和修改成功；创建得到持久化 ready Task，可从列表进入详情。
3. 冻结配置不随草稿修改；同一创建命令重放返回原结果；取消后状态来自权威快照。
4. 未执行能力不暴露可成功提交的 start；没有目标请求或 Runtime 创建。模型请求仅限计划冻结后的显式连接检查；普通保存、预览、创建不调用模型。模型管理权限与连接检查的具体验收项待补齐。
5. Viewer 写入、跨项目与非作者草稿访问拒绝；过期/不兼容授权与版本冲突明确展示。
6. 原有任务和回执保留，新执行能力不能自动执行旧 queued。

测试仅主流程和直接受影响边界。整个前置任务（原型与正式接入）共享 600 秒检查预算，不能按两个批次、代理或修复重置。关键未过保持 partial；不为本阶段重跑 Phase 1A/B 全量。
