# Phase 1C 前置：0.5 配置与任务创建 Spec

- 状态：draft / 可评审草案，未批准业务实施。
- 日期：2026-09-10；起点：codex/phase-1c-prep@4b3feb4。
- P0已验收；本草案只承接其模型工厂与受限Provider适配，不扩大P0结论。正式规划需在应用Plan模式完成，不能由代理自行切换。
- 依据：根AGENTS、project-context、scenario-execution-design、agent-harness-decision、P0 acceptance及用户最新确认。

## 1. 目标与首批范围

交付“管理员配置模型 → 创建者选择Web单点场景 → 保存/恢复草稿 → 确认范围 → 预览 → 创建待启动任务 → 查询/取消”的真实配置闭环。

新版原型展示CTF、Web单点、综合渗透、攻防演练、代码审计五类差异；正式版本先开放Web单点。所有场景的执行能力仍关闭，不创建Runtime、不访问测试目标、不运行Agent、不实施流量控制/黑板/资料导入。模型服务只支持已适配的OpenAI Chat Completions与Anthropic Messages；不新增Responses、fallback或多模型路由。

模型预算采用Token总上限，金额上限不开放。用户已确认：没有可用模型方案时只能保存草稿，配置好模型后再创建任务；不得创建缺模型的待配置Task。

## 2. 产品交互

### 2.1 组织基础配置

入口为基础配置 → 模型服务。用户先选组织；管理员可管理，普通成员只在任务创建中读取允许使用的已发布模型方案。

| 操作 | 用户输入 | 默认与高级项 | 系统行为 |
| --- | --- | --- | --- |
| 新增模型服务 | 显示名称、协议、Base URL、API Key | 默认OpenAI兼容；高级展开请求超时与共享配额组 | 保存配置，不触发模型请求；Key只写不回显 |
| 配置模型方案 | 方案名称、服务、真实模型ID | 首批一个方案绑定一个模型；主/摘要用途以后沿用同一受控配置，不建角色模型矩阵 | 模型ID先明确填写；本批不增加自动全模型发现/遍历验证 |
| 连接检查 | 点击已保存版本的检查按钮 | 固定短合成文本、一次请求、最大256输出、无自动重试；检查是显式外部调用 | 显示检查中/成功/失败/结果不明、时间与上游用量，不把连通等同于工具或推理能力通过 |
| 发布/停用 | 确认对应版本 | 本草案建议当前版本连接检查成功后可发布；旧版本不可就地覆盖 | 创建页只列已发布且启用方案；任务中的历史快照保持可查看 |

修改Base URL、协议、Key或模型ID形成新版本，旧检查不能自动覆盖新版本；仅改显示文案不伪造新的能力证据。停用影响新建和未来启动，既有任务记录保留。不提供密钥读取/导出与批量自动检查。

配额组表达共享上游账户关系，由管理员明确选择或确认；未知映射显示未确认，不按URL/模型名自行判断。本批保存关联与限制配置，不宣称已完成生产多副本配额调度。

### 2.2 Web 单点创建四步

| 步骤 | 用户填写/确认 | 系统默认 | 高级内容 |
| --- | --- | --- | --- |
| 场景与目标 | 选Web单点、系统入口、可选目标说明 | 根据入口建议可编辑名称；默认匿名 | 自定义关注点；不出现账号密码表单 |
| 对象与范围 | 确认域名/子域、协议/端口、授权依据与有效时间 | 精确入口主机、入口协议/端口，不包含子域；路径仅作关注点 | 增加明确的主机/端口与排除主机；不提供路径ACL，不执行DNS或资产探测 |
| 运行配置 | 选择已发布模型方案、确认任务Token与时间预算 | 有唯一可用方案时预选；其他默认值来自服务端创建选项 | 工具轮数/请求节奏等计划值；DNSLog、代理、运行环境未实现时只说明状态，不收集随后会被忽略的参数 |
| 确认 | 查看场景、目标、范围、模型版本和预算，显式确认授权 | 服务端预览列出缺项和冲突 | 无 |

所有步骤均可显式保存部分草稿，只有保存成功才显示已保存；刷新从服务端恢复。表单不展示内部DTO字段名、HTTP Adapter等开发批次入口。

预算数字不沿用P0的4次或256输出限制。本草案不发明未经确认的项目默认数值：创建选项返回已有项目模板；没有对应默认时要求填写，草稿允许空缺。具体业务默认值在Plan评审中定稿。

范围确认属于任务创建者的声明记录，绑定真实用户和具体草稿版本，不提升为组织级Scope管理权限。创建或预览不得访问目标。外域依赖加载与主动测试仍分权，具体执行策略留在后续阶段。

### 2.3 创建与详情

保存草稿、创建待启动任务、启动执行是不同动作。新任务状态ready；本批start不可用并给出能力原因，不建立无人消费的执行队列。ready可取消，结果以服务端快照为准。

列表显示名称、场景、目标摘要、状态与时间；详情显示范围、模型/配置版本、预算、允许动作和事件。使用现有五主题、分页、幂等回执核对与迟到响应隔离，不重新设计视觉系统。

## 3. 数据与权限行为

- 新增独立task_drafts，支持不完整输入、作者、项目、场景、版本、更新时间；只有原作者且仍有项目写权限才能编辑，Viewer不能访问他人草稿。
- 新增不可变task_scope_confirmations，包含用户、草稿ID/版本、规范化范围摘要、授权声明与有效时间。范围或草稿版本改变后须重新确认；不复用旧确认扩大授权。
- 预览保持短有效期，绑定草稿/确认/权限版本及模型方案版本，存完整规范化输入摘要。预览不是长期草稿。
- 创建事务重新鉴权并核对草稿版本、预览、确认有效性、模型可用性，冻结ConfigSnapshot，同时写Task、原提交者回执和事件。同键重放先重新鉴权，再返回已有结果，不重复检查旧预览或重新创建。
- TenantAdmin采用独立的组织管理能力，保留现有项目Operator/Viewer判断；管理员身份不隐式授予所有项目访问权。管理调用复用用户事务锁和permissions_version协调撤权。
- 模型服务、方案版本、检查记录按组织隔离；Key只由受信Provider边界保管，数据库与Task快照只存secret_ref。API写入时短暂接收用户提交的Key并转交受信存储，不落日志、不进入Harness或会话。
- 凭据持久化首批候选为本机私有目录后端（0700/0600、版本化secret_ref、原子写、只读Provider），保持与P0的本地边界一致；是否本批直接改用Kubernetes Secret须在Plan评审决定。不得把这个待决项交给开发代理自由选择。
- 模型连接检查为组织配置操作，有独立检查ID、版本、状态、用量与幂等键；不挂虚构Task。请求已发送且结果不明时保留记录，不自动换键/重试。仅管理员主动触发，模型配置保存和任务创建不隐式检查。

## 4. 兼容与失败

公开契约拟升级0.5.0，业务路径继续使用/api/v1；生成类型/校验器与前后端同时升级。

旧queued任务、旧Scope、命令回执及事件原样保留，新记录标注配置schema版本。删除“所有任务版本只能1/2”的数据库约束，版本仍单调递增；旧queued不转换成曾经ready/start，未来执行器不得自动接管。旧路径Scope不删字段扩权，创建新域名级范围确认时重新声明。

401清理身份视图；不可见资源404；可见但无写权限403；参数422；版本/幂等/无效状态冲突409。表单失败保留输入，结果不明继续按原键只读核对。模型检查失败不产生已发布/已验证假状态，草稿内容仍可保留。

本批不做历史数据破坏性迁移或重置seed，不重跑Phase1A全量验收。Phase1A保持partial，master保持原基线。

## 5. 最小验收与待决项

最小验收：一个管理员配置模型并完成受控夹具检查；一个Operator保存草稿→刷新→确认范围→预览→创建ready→详情→取消；合并覆盖Viewer/跨组织/非作者拒绝、同键重放、草稿版本冲突和旧queued兼容。

沿用剩余174秒共享检查预算，原型/后端/前端/环境准备共同累计，不重置；P0的真实模型4次额度已耗尽，本批开发验证使用本地夹具与既有证据，不追加真实上游请求。功能中的手动连接检查须在本阶段计划批准后实现，不把当前P0额度用作自动测试授权。

正式开发前待评审：凭据持久化后端、服务端预算默认值、模型发布是否必须绑定成功的同版本连接检查、检查作业与本地生命周期的具体接入。其余已确认需求不重复询问。
