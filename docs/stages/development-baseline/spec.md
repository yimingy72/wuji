# 开发基线 Spec

- 状态：approved；依据用户批准的《Wuji 分阶段开发与验收流程》实施
- 日期：2026-09-09
- 阶段：development-baseline
- 基线：当前 v0.4 架构、OpenAPI 0.1.0、独立前端原型；此前没有 Git 提交

## 目标与范围

将已确认协作方式变成仓库规则、可复用阶段文档、独立子代理交付过程和有验证记录的本地 Git 基线。保留现有前端、契约与五套主题；本阶段不实现 Phase 1A 业务 API、身份或数据库。

主代理同时准备 Phase 1A Spec / Plan 草案，列出已研究的明确默认方案与实施依赖；草案状态单独记录，不能把编写草案当作完成 Phase 1A 开发。

## 交付与行为

- 根目录 AGENTS.md 保留原有验证/CodeGraph 规则，记录角色、模型、阶段文档、worktree 和验收制度。
- 开发指南提供从规划到验收的实际步骤，阶段模板覆盖 Spec、Plan 和验收记录，包含变更归属与测试提交 SHA。
- 根目录 README 和开工文档能导航至协作流程、当前阶段及后续草案，状态与实际工作一致。
- 本地 Git 使用已选项目身份，保存现有文件快照与阶段提交；不配置或推送远端。
- CodeGraph 同步主工作区已有索引；无法检索时记录原因并使用文件搜索，不以索引失败阻止已获授权的工作。

## 验收标准

| ID | 可观察通过条件 |
| --- | --- |
| B01 | 当前源码、锁文件、契约和架构有可回溯 Git 快照；暂存/提交不含真实凭据、依赖、构建或运行产物 |
| B02 | AGENTS.md 与开发指南中的模型、角色、并发、授权和 Git 规则一致；无已实现平台的误导表述 |
| B03 | 开发代理使用 SOL/xhigh，测试代理使用独立 SOL/high；任务范围、分支和 worktree 可核对 |
| B04 | 三种阶段模板可直接填写，含状态、范围、决策、依赖、验收及被测 SHA；当前阶段已有具体 Spec / Plan |
| B05 | 使用项目固定 Node/pnpm 完成冻结安装、契约/类型/现有测试及构建；与原记录差异明确解释 |
| B06 | 在本机可用 Chrome 或配套 Chromium 上执行现有浏览器用例，记录实际浏览器/端口/结果；不占用原型评审服务 |
| B07 | 对实际测试 SHA 检查源码、文档链接与 Git 忽略范围；主代理复核关键契约及至少一条交互证据 |
| B08 | 当前基线验收与 Phase 1A 草案分开；后端/Runtime/Harness 尚未验收项保持未完成 |

## 接口与失败处理

本阶段不改变公开 API、OpenAPI 字段或生产依赖。模型不可用、缺少固定工具链、测试失败、索引失效均报告实际结果；不通过降级模型、关闭校验、覆盖变更或修改全局配置绕过。必要修复按同一阶段 Plan 分派并复测。
