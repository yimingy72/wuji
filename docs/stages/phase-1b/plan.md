# Phase 1B Plan：范围、任务与事件

- 状态：B1 implemented（最小验证通过）；B2/B3 in-progress，已批准统一[具体实施计划](b23-plan.md)，不重复审批内部交接。
- 对应：[Spec](spec.md)；候选基础为 Phase 1A 阶段分支，实际开工时固定 SHA。
- 约束：沿用根 AGENTS.md 的 Plan 流程、SOL/xhigh 开发、Luna/xhigh 集中测试及共享 10 分钟测试预算。

## 1. 评审结论与首批入口

首批已细化为[B1 Spec](b1-spec.md)和[B1 Plan](b1-plan.md)，独立只读评审见[记录](review.md)。固定OpenAPI 0.3.0、新task.preview权限及创建不可用blocker；URL规范化、范围导入、分页、纯计算预览和登录回跳均有明确方案。B2未执行任务取消采用单事务queued→cancelled和not_granted，避免增加恢复进程。公共契约与生成物由开发A唯一负责，先集成后交B接入。

不更换已锁定技术栈，不为本阶段引入 Agent Harness、消息中间件或新集群。CodeGraph 先定位身份、项目事务、分页、API 客户端及路由；核对当前工作树后复用已有模块。

## 2. 任务、归属与交付顺序

| 顺序 | 负责人 | 唯一修改范围 | 交付 |
| --- | --- | --- | --- |
| B1-A | SOL / xhigh 开发 A | apps/api、scripts/platform 管理入口；全部迁移/契约/生成器/manifest/锁文件/根命令 | Scope 存储和预置；纯规范化/范围计算；scopes 与 previews API；生成响应校验器 |
| B1-B | SOL / xhigh 开发 B | apps/web 非 manifest 源码；必要主题组件样式 | 真实范围选择和任务预览表单；依赖 B1-A 固定契约 |
| B2-A | 开发 A | API 业务模块、迁移与权威契约 | Task/CommandReceipt、权限扩展、创建和取消、列表/快照/回执 API；同事务事件 |
| B2-B | 开发 B | apps/web 非 manifest 源码 | 创建、任务列表/详情、取消和原键核对；依赖 B2-A 固定接口 |
| B3-A/B | 对应开发者 | 各自原范围 | 事件补页与前端刷新、最终交付；不得趁收口扩张执行能力 |
| 集中验证 | Luna / xhigh | 新批次测试和记录，不改产品代码 | 按 Spec 取最小证据，保留延期清单 |
| 集成 | 主代理 | 阶段文档、分支集成和审查 | 固定候选 SHA、核对关键差异和证据；诚实记录部分/完整交付 |

每个任务使用独立 `codex/phase-1b-<task>` 分支和 worktree，任务书写明绝对目录、起点 SHA、范围、依赖与测试剩余预算。后端每批先交付公共契约，再允许前端依赖它；同一文件不可并行改写。B1具体任务和验证命令已在批次Plan固定，本表不直接触发业务实现。

## 3. 精简验证方案

| 批次 | 必要检查 | 延后集中覆盖 |
| --- | --- | --- |
| B1 | 一个合法预览；一个路径边界拒绝；一个跨项目拒绝；前端构建 | 扩展 URL 编码矩阵、所有主题逐一截图 |
| B2 | 创建→刷新读取→取消；同键同请求只有一个任务、变更请求409；Viewer写入拒绝 | 多进程并发压力、复杂网络故障组合 |
| B3 | 快照接续事件无缺口；原键核对复用原回执；一次关键页面走通 | 全量回归、长时间断线与性能测试 |

B1精确测试文件与命令已在批次Plan固定，其余批次开工前补齐；使用已有Python/Playwright启动路径，不引入第二套平台启动器。工程检查按改动选择pnpm contracts:check、pnpm build:platform与定向pytest/Playwright，而不是每次串行执行所有命令。安装仅在依赖变化或环境缺失时进行。

不因测试辅助代码或 SHA 变化重跑 Phase 1A 的 73 个 API、6 个生命周期用例。Phase 1A 的三个延期回调用例单独保留原清单；开发 B1 不自动重新启动该测试循环。集中批次并发只用于不争用端口、数据库或身份的任务。
