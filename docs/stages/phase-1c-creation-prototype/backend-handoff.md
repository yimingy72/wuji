# D3-B 后端与正式前端衔接清单

状态：review draft，不授权直接迁移或业务开发。D3-A用户交互确认后再冻结D3-B Spec/Plan。

2026-09-11 主开发续接：已形成[D3-B具体Spec](../phase-1c-task-creation/spec.md)、[Plan](../phase-1c-task-creation/plan.md)、[五场景Goal模板](../phase-1c-task-creation/goal-templates.md)及[调度合同提案](../phase-1c-task-creation/execution-handoff.md)。这些仍为draft，以下清单保留为来源；D3-A原验收不新增Goal能力，也未伪造用户通过。

## 已有能力

D1 SavedTaskDraft支持五场景不完整输入与版本化保存；D2支持TenantAdmin、模型服务/方案版本、显式检查、发布/停止发布/安全撤销、原操作查询。正式Task目前只支持queued/cancelled。原型不连接这些接口，内存状态不能作为实现或验收证据。

## 创建与范围

- Web首批在草稿补齐valid_until、包含/排除规则与确认依据；确认人、时间及归属从服务端身份产生。期限为空/已过期时可保存草稿，不能创建。
- 包含规则表达host、是否含下级、scheme/port组合；排除默认覆盖主机及子域和本任务所有协议端口，允许缩小组合。排除优先，入口被排除/不包含/有效范围为空拒绝创建。
- 当前D1的include_subdomains/additional_origins不足以表达每条规则和排除；原型的独立includes/excludes是未来类型，不能直接原样冒充D1请求。用新Schema区分新范围与旧路径Scope，保留旧字段、复合FK和历史语义。
- 新授权仅绑定本Task，不改变其他任务或项目范围；不能把删除旧路径字段当作全域授权。
- 预览绑定完整草稿版本、模型版本、Scope摘要与确认内容；正式创建时重新鉴权并复核期限、模型发布/撤销状态。确认后修改对象/范围/期限使确认失效。

## 命令与快照

- 保存草稿、创建Task、启动分开。复用现有命令幂等键/回执与权威快照，不新增无法消费的start。
- 正式客户端沿用sessionStorage最小标记：用户/项目/命令键/资源ID/时间；正文只在内存。unknown与明确拒绝分开，回执404不能推断未创建；刷新不重构请求。
- 每项目一个待确认命令；原键原请求重试，不自动换键。读回执后再读Task；查看列表并明确放弃核对后才允许新操作，不删除原Task。
- 迟到回调同时检查用户/项目代次和提交键；身份切换不能让旧回调覆盖后来同项目的新命令。
- 增加ready并调整数据库/DTO/生成器/列表详情；历史queued无start记录不得自动执行。
- 固定创建时目标/包含排除/期限/模型版本及计价/Task金额快照；模型后续变化不改历史。Runtime/工具版本未具备时不能填入虚构版本；执行快照和准入依赖须在D3-B方案中明确。
- 2026-09-11 后续需求确认：平台按场景提供默认 Goal/完成条件模板，创建任务允许自定义，权威语义见[评估配置契约](../../assessment-model.md#21-配置契约)。D3-B 冻结时明确模板与任务实际目标的版本/快照关系及交互；这不是 D3-A 已验收能力，不据此直接修改原型或开放执行。

## 模型与权限

- 服务新版本仍要求Key重输，不以掩码或旧版本引用代替；成功后清输入，结果不明先按原操作核对。Key不进入浏览器持久化、原型模型记录或普通日志。
- 方案复用已有服务版本不要求Key；名称、服务版本、模型ID必填，容量缺失可保存不可发布。价格整体为空可保存/检查；填写后来源、输入输出价、显式cache_mode齐全才保存。
- standard_input不提交独立缓存价格，切换时清除旧值；separate需两项缓存单价。上下文/输出Token是模型能力，不是Task金额预算。
- revoked先立即使平台选择失效，网关阻断单独pending/confirmed；不将“网关确认阻断”解释为在途全部停止。草稿保留旧版本名称/失效原因，不自动换模型。
- 正式页面读取D2当前权限与发布状态，不把本地演示角色切换当成鉴权。同步扩展路由/登录回跳白名单。

## 原型差异

原型仅提供可重置内存数据；实际reload会清任务/回执/表单，只有主题保留。“模拟刷新”是丢弃客户端原请求并保留内存服务端和标记的评审动作。取消仅针对从未执行的ready任务，不是运行时停止验证。暂无资料导入、DNSLog、代理、Kali、Cairn调度或真实金额计费。
