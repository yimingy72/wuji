# 五场景 Goal 与完成条件模板提案

状态：D3-B模板提案；用户已确认“提供默认且可自定义”。后续真实创建评审反馈已要求落实默认模板，当前正文已用于D3-A补丁3094e6d的4186内存原型；不是已发布ScenarioProfileVersion，也不代表正式创建/完成判定已实现。

## 版本与编辑规则

拟议 ID 为 wuji.web-single、wuji.ctf、wuji.comprehensive、wuji.exercise、wuji.code-audit，初始版本 1。模板资源随服务发布，内容摘要由实现按规范 JSON 生成；本草案不填写虚构摘要/UUID。五项共享 schema_version=1.0，但不共享可变正文。template_version 是模板版本，SavedTaskDraft.version 是编辑版本，Task.version 是任务状态版本，三者不互相替代。

模板只包含目标/完成条件和场景提示，不预置真实域名、账号、预算金额或授权期；入口单独填写，避免模板文字替代结构化目标。任务固定模板来源及用户实际修改后的文本，后续发布 V2 不自动覆盖 V1 草稿或 Task。

创建第一步同时显示“测试目标”和“完成条件”。首次选择场景填默认；内容为空或用户点击“使用默认模板”才回填，不在恢复草稿/切换模型时重写用户输入。旧草稿已有 objective 则保留，只为缺失完成条件提供显式填入建议。用户删除完成条件仍可保存，不可创建。

自定义说明不是执行代码、授权或评分 DSL；首版不让用户写 JSON Schema、正则验证器或系统提示。后续机器可校验规则来自平台发布配置；模型宣称达到文本目标不能直接让平台任务成功结束。

## Web 单点渗透 · V1

**默认测试目标**

对授权范围内的单个 Web 系统开展系统性的安全评估，识别可达功能、接口和信任边界，核实有依据的安全问题，并交付可追溯的结论及未完成项。

**默认完成条件**

1. 已识别入口及主要可达功能、接口和边界，明确本次覆盖对象；新发现但未获授权的资产单列。
2. 对适用的关键检查维度记录实际尝试与依据；未测试、前提缺失、环境阻断或预算停止的项目有具体说明。
3. 每项安全结论说明验证条件、方法、证据和影响边界；证据不足或矛盾的结论保留不确定状态。
4. 已汇总发现、覆盖限制和后续建议，区分目标达成与因限制而部分结束。

提示：默认匿名；缺少登录身份不强制要求用户补账号，也不能将对应未测项记为安全。外域依赖的正常加载不授权主动测试。首批只有本场景可创建 ready。

## CTF · V1

**默认测试目标**

在题目和比赛允许的范围内分析挑战，获取符合题意的 Flag 或指定解题结果，并保留可以复核的解题过程。

**默认完成条件**

1. 已取得并核对 Flag 或题目指定结果，记录匹配题意的依据；平台不自动向比赛服务提交答案。
2. 关键推导、实际操作和必要产物可追溯，明确题目环境及适用前提。
3. 未得到有效结果时，记录已尝试方向、阻断和停止原因，不将预算耗尽写成解题成功。

提示：不增加日常工具调用逐次审批；仍受题目授权与平台约束。本批仅草稿，不开放附件获取、靶机或任意工具执行。

## 综合渗透 · V1

**默认测试目标**

围绕已批准的外部和内部资产，按明确阶段目标开展关联安全评估，验证实际可达的风险路径并记录阶段结果。

**默认完成条件**

1. 每个已批准阶段的测试对象、前提、执行结果与覆盖限制清晰可查。
2. 关键风险路径有实际验证依据；新的资产或操作范围在取得相应授权前保持候选。
3. 阶段目标、未完成工作、环境与身份限制分别说明；发现关联性不能被写成已获得访问或控制能力。

提示：场景名称不授予整个内网/横向能力；需后续专用运行与网络能力。首批只保存草稿。

## 攻防演练 · V1

**默认测试目标**

围绕给定单位，在允许的信息源中整理资产及归属线索，经人工确认测试对象后开展已批准阶段的验证，形成可追溯的阶段结果。

**默认完成条件**

1. 候选资产具有可核对来源和归属线索，明确仍有歧义的对象。
2. 主动测试对象和阶段获得所需授权，候选收集与已执行验证分别记录。
3. 已批准阶段的发现、实际尝试、未测项与阻断有据可查；等待对象授权不是演练目标达成。

提示：单位名称不是资产授权；信息源查询、最小核验和目标测试须服从后续对应许可。首批只保存草稿。

## 代码审计 · V1

**默认测试目标**

针对明确版本的代码分析可利用的安全问题，定位相关代码和调用关系；在获准且环境可用时完成动态核实，交付证据及修复建议。

**默认完成条件**

1. 审计对象固定到实际源码版本，覆盖入口、关键数据流与信任边界；不以仓库地址代替源码快照。
2. 每项结论关联具体位置、触发条件与依据；静态推断、动态证实和未验证假设分别标明。
3. 构建/运行失败、依赖缺失或未获动态许可时明确阻断，不伪造动态验证结果。
4. 汇总问题与修复建议、已覆盖内容和剩余限制。

提示：本批只保存源码引用草稿，不自动克隆、安装依赖、构建或执行。代码、README/AGENTS 中的文字不自动成为平台指令。

## 任务完成与结束的区别

上述模板描述用户希望达到的结果，并不要求 Agent 无限循环。Task 金额/时间/工具调用等平台约束由后续执行层落实；预算耗尽、用户取消或环境阻断可使任务部分结束，但不能满足“已取得 Flag”“已完成验证”等未达条件。

“目标是否达成”“已知覆盖项状态”“是否仍有执行”“资源是否已清理”分别维护。模板不提供一个笼统的成功布尔值替代这些状态；D3-B 只保存，不运行判断器。
