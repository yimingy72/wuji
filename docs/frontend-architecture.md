# Wuji v0.4 前端架构与技术选型

- **日期**：2026-09-09
- **状态**：前端实施设计及当前边界；正式 `apps/web` 已随 Phase 1A/1B 集成，Phase 1A 完整验收为 `partial`，B2/B3 主流程最小验收已通过；扩展平台验收、Runtime 与 Harness 仍未完成
- **上游约束**：[平台架构](architecture.md)、[评估、知识与交付模型](assessment-model.md)
- **验收依据**：[架构验收清单](architecture-acceptance.md) F01–F12，及各页面涉及的平台验收项

## 1. 决策范围

Wuji 首版前端是登录后使用的安全验证控制台，主要处理任务创建、长任务状态、验证记录、证据和报告。采用 React + TypeScript + Vite + Ant Design，作为独立静态应用，经同源入口访问 Platform API。

本设计固定框架方向、状态归属、接口边界、登录方式、页面顺序和部署方式。精确依赖先经独立原型兼容性检查并写入锁文件，随后用于正式 `apps/web`；当前实现与验收进度见 [Phase 1A 验收](stages/phase-1a/acceptance.md)和 [Phase 1B 验收](stages/phase-1b/acceptance.md)。原型结果仍只证明原型本身，不能替代正式平台证据。

当前假设团队没有必须沿用的 Vue/企业脚手架，产品以桌面浏览器和私有化部署为主。若已有成熟团队基座，需补充迁移与维护成本再修订此决策。品牌视觉、复杂图布局和全量配置表单可以随对应阶段细化。

## 2. 技术选型与取舍

| 层次 | 首版决策 | 原因与边界 |
| --- | --- | --- |
| 应用与语言 | React、TypeScript strict | 将任务状态、权限和契约建模为显式类型；运行时输入仍需校验 |
| 构建与渲染 | Vite、浏览器端 SPA | 适配独立 API 和静态交付；首版没有公开页面 SEO 或服务端渲染需求 |
| UI 组件 | Ant Design 6.6.3 + React 19.2.8，已在原型固定并用于正式应用 | 表单、表格、详情和状态操作是核心页面；扩展集成仍按阶段验证 |
| 路由 | React Router Data Mode | 统一嵌套路由、懒加载、加载和错误边界；数据通过同一查询层访问 |
| 服务端数据 | TanStack Query | 管理请求、缓存失效和重新获取；数据库状态的浏览器投影，不承担业务决策 |
| 页面状态 | URL 参数 + React 局部状态 | URL 保存可分享的筛选/分页/选中项；局部状态保存表单和抽屉；首版不另建全局任务状态库 |
| 实时更新 | REST 命令/查询 + SSE 通知 | 控制请求走 API，持续事件用于刷新视图；Phase 1 可先使用有界只读轮询 |
| 样式 | Ant Design tokens + CSS Modules | 统一主题和语义颜色；页面布局样式限制在模块内 |
| 接口契约 | OpenAPI + 共享事件/业务 JSON Schema | 生成 TypeScript 客户端类型，关键响应及事件执行运行时校验 |
| 工程管理 | pnpm workspace、锁文件、固定 Node 工具链 | 前端与共享契约在同仓库维护，开发与 CI 使用同一版本 |
| 验证工具 | Vitest、Playwright | 分别覆盖状态/事件处理和真实浏览器工作流；测试运行器与平台 Browser Adapter 分开 |

Ant Design 6 要求 React 18 或以上；React 19 可以作为候选，但这不能替代对路由、组件、图标和构建工具组合的验证。[Ant Design 6 迁移说明](https://ant.design/docs/react/migration-v6-cn/)

React Router Data Mode 提供路由数据加载与 action 能力。Wuji 中 loader 复用 TanStack Query 的查询定义，写操作也走统一命令客户端；同一资源不再维护一份独立的路由数据缓存或另一条写入通道。[React Router 模式说明](https://reactrouter.com/start/modes)

首版使用基础 antd 和项目自己的 AppShell。ProComponents 可在重复 CRUD 模式出现后局部引入，Ant Design X 可在需要对话组件时评估；任务生命周期和工具记录使用 Wuji 领域 Schema，不由聊天组件定义。完整 Pro/Umi 脚手架、Next.js、额外 BFF 都不属于本次默认依赖；出现必须的组织基座、公开页面或服务端聚合需求时再记录新决策。

图谱先采用列表、关系详情和证据链表达。等到全图交互的节点规模、布局、编辑与回放需求明确，再比较图组件；本阶段不同时引入多套图引擎。

## 3. 工程边界与状态归属

正式控制台已建立在 `apps/web`，并使用 `packages/contracts` 与 `packages/theme`；本地原型继续位于独立的 `spikes/frontend`。当前 `apps/web/src` 采用较平的模块结构，业务增长时按下列边界拆分，不为对齐示意目录做无收益搬迁：

```text
apps/web/
  src/app/                  # 启动、路由、AppShell、Provider、主题
  src/features/tasks/       # 创建、任务列表、控制、详情
  src/features/assessment/  # Coverage、Verification、Finding
  src/features/evidence/    # 证据检索和受控预览
  src/features/reports/     # 快照、版本和导出
  src/shared/api/            # 客户端封装、错误、Schema 校验
  src/shared/auth/           # 会话与项目上下文
  src/shared/events/         # SSE 生命周期、去重、缓存失效
  src/shared/ui/             # 少量跨业务通用展示组件
  tests/                    # 单元、组件与端到端测试
packages/contracts/         # API、事件及业务 Schema；生成物不手工修改
packages/theme/             # 五套共享主题、语义颜色及 Ant Design tokens
```

页面通过 feature 的查询/命令接口访问数据；跨 feature 使用公开接口和共享契约，不相互导入内部组件。`shared` 只放已有复用需求的内容，不预建一套包裹所有 antd 组件的通用框架。

| 状态 | 唯一归属 | 示例 |
| --- | --- | --- |
| 业务权威状态 | Platform API / PostgreSQL | Task、Scope、权限、FindingRevision、ReportCommit |
| 浏览器查询缓存 | TanStack Query | 当前任务快照、分页验证记录、可查看证据列表 |
| 可分享视图状态 | 路由和 URL 查询参数 | project/task ID、页码、非敏感筛选、详情 Tab |
| 未提交交互 | 页面局部状态 | 表单草稿、抽屉展开、选中行 |
| 会话和项目上下文 | 应用会话层，来源为服务端 | 用户、有效权限、当前项目、上下文代次 |

查询键至少包含资源归属的 tenant/project、资源 ID 和影响结果的筛选/版本。路由参数是请求条件，不是授权证明。敏感目标凭据、原始请求正文和证据内容不进入 URL、浏览器持久存储或埋点。

切换项目、注销或权限失效时，先提升上下文代次，再关闭订阅、中止请求、清理对应查询缓存及未提交敏感表单、撤销预览对象 URL。迟到的响应和事件必须检查代次及资源归属后才能写入；仅清空缓存不足以阻止旧请求回填。已向用户交付的数据无法通过清空页面追溯收回。

## 4. API、命令与事件同步

### 4.1 开发前要冻结的契约

下表是接口能力要求；Phase 1 已落为 [OpenAPI 基线](phase1-api-contract.md)，Phase 1A/1B 已实现身份、项目、Scope、任务、命令回执和事件补页等当前切片。实际目标执行、Runtime、SSE 持续订阅及 Harness 仍属后续能力。具体路径、字段和错误枚举以 OpenAPI/JSON Schema 为准，不在页面里各自推断。

| 接口能力 | 必须返回或约定的内容 |
| --- | --- |
| 会话与项目 | 当前身份、项目权限/能力、权限版本、会话有效性；无访问权的资源不返回详情 |
| 创建预览 | 规范化目标、有效 Scope 版本、期限、排除项、限额、缺失前提、输入摘要及预览有效期 |
| 创建与控制命令 | 幂等键、请求摘要、接受/拒绝结果、关联资源 ID、用于后续查询的命令标识 |
| Task 快照 | 执行状态、清理状态、版本、当前 Scope 绑定、允许操作、业务 outcome/stop_reason（对应阶段启用） |
| 快照与事件交接 | 与快照一致的订阅游标，以及从该位置补发的保证；游标不代表访问权限 |
| 分页数据 | 稳定排序、游标或页码规则、可选总量、服务端上限；事件不会改变分页契约 |
| Artifact / Report | 可查看元数据、独立下载权限、固定 revision/commit、失效原因和保留信息 |
| 错误 | 机器可读 code、字段错误、可安全展示的说明、trace ID、必要时当前版本或重试时间 |

创建时携带预览绑定的输入摘要及策略版本；服务端重新校验授权、有效期和输入一致性。版本过期或权限变化时，返回需要重新预览的冲突，不静默套用更宽的范围。Phase 2 再将场景与知识版本纳入 ConfigSnapshot，Phase 1 的基本范围预览不能依赖尚未交付的配置中心。

组件不维护第二套手写 Task 状态枚举。关键响应、事件信封及状态字段在 API 边界执行 Schema 校验；未知必需版本触发“客户端需要更新”或受限错误页，不能当成已完成/空结果。生成器与校验器的具体包在契约验证时选择，并确认支持所采用的 OpenAPI/JSON Schema 版本。

### 4.2 命令接受不等于执行完成

创建、暂停、恢复、取消、报告生成都走统一命令客户端。按钮可以立即显示“正在提交”，成功接受后显示服务端返回的状态；不能在收到 HTTP 202 后将任务直接改成 cancelled、paused 或 completed。

取消请求接受后查询权威任务状态：B2未执行的queued任务可在同事务直接cancelled；Phase1C的实际执行停止才涉及cancelling、unknown调用或cleanup_pending。命令超时表示提交结果待核对，使用原幂等键查询或重送同一请求；相同键不同请求内容由服务端拒绝。不得自动生成新键反复提交。B2/B3用sessionStorage只保存原键与归属元数据，完整请求只留内存，刷新后只读核对、不猜测重送。幂等键保留期覆盖允许的重试窗口。

只读查询可有次数上限的重试；401、403、明确业务拒绝不循环重试。写操作默认无通用自动重试，重试入口服从上述命令契约。分页、筛选和详情加载失败不呈现为“没有结果”。

### 4.3 SSE 与快照恢复

首版 SSE 用于服务端向浏览器通知变化，浏览器命令继续使用 REST。EventSource 提供事件 ID、断线重连和关闭能力；Wuji 自行实现下面的业务补发与鉴权契约。[MDN SSE 说明](https://developer.mozilla.org/en-US/docs/Web/API/Server-sent_events/Using_server-sent_events)

1. 先获取带版本和一致游标的快照，再从游标订阅；快照读取期间发生的事件必须能够补发。服务端不能简单返回与快照无一致性保证的“当前最新事件 ID”。
2. 事件信封包含 Schema 版本、事件 ID、资源归属、聚合 ID/版本、事件类型和发生时间。使用同一流的事件 ID 去重、同一聚合的版本防回退；不同资源不比较版本大小。
3. Phase 2 优先让事件标记相关查询失效，批量重新获取权威快照；大证据正文不通过 SSE 推送。重新获取的结果也需检查版本，防止慢请求覆盖更新的缓存。TanStack Query 提供缓存失效和后台重新获取机制。[TanStack Query 缓存失效说明](https://tanstack.com/query/latest/docs/framework/react/guides/query-invalidation)
4. 同一 EventSource 的重连使用 Last-Event-ID；重新创建实例时可传入最后确认处理的非敏感游标。服务端接收头部游标时优先于初始查询参数；两者均只决定补发位置，均需重新鉴权。
5. 游标超出保留期、Schema 不兼容或发现版本缺口时，停止使用旧事件刷新状态，进入重新同步流程并获取快照。应用记录的游标在事件校验和处理成功后才推进；原生 EventSource 接收时更新的 last event ID 不能充当业务处理确认，处理失败应关闭旧实例并从已确认位置或新快照恢复。
6. 每个页面实例对当前 Task 维持一个共享订阅，Tab 和组件复用它；切换任务/项目或离开页面时释放。列表页使用分页查询和有界轮询，后续如需项目级订阅再定义协议，避免为每个任务建连接。

连接管理层统一选择重连策略：原生自动重连期间不再启动另一套重连循环；若需自行退避，先关闭原 EventSource，再按有上限的退避和抖动重建。连接失败先核对会话/资源访问结果，明确失权时停止重连并清理页面。显示“连接中断，数据更新于……”和重新同步状态，不用连接图标暗示任务已经停止。

Phase 1 可以按配置周期查询快照和事件历史，限制并发、退避和后台页面刷新频率；Phase 2 替换为 SSE 后保留低频一致性查询。两种方式都只读状态，不因断线而重发目标操作。

Agent 框架事件先由服务端转换为领域事件，不把 SDK thread ID 或内部控制协议直接交给浏览器。状态、工具和证据使用持久事件；以后启用逐 Token 展示时，文本片段为有界临时流，不逐片更新 Task 版本或写入 Outbox。断线后恢复最终可见摘要与业务快照，不要求重建隐藏推理或逐 Token 历史。

## 5. 登录、权限与证据边界

首版采用浏览器与 Platform API 同源的服务端会话。生产会话 Cookie 使用 HttpOnly、Secure 和明确的 SameSite 策略；优先 SameSite=Lax，身份提供方回调若要求调整需单独验证。API 写请求同时验证 CSRF Token 和允许的 Origin，不能只依赖 Cookie 或前端按钮状态。CSRF Token 可以由会话接口提供并保留在内存，它不是登录凭据。

首个登录提供方已选定为 Keycloak OIDC，前端消费统一会话接口；Phase 1A 已实现登录、会话、退出及项目权限基础闭环，但三个真实 Keycloak 回调用例延期，完整验收保持 `partial`。后端管理 OIDC Token，Provider Key、Runtime 凭据和可复用登录 Token 不进入前端包或 localStorage。返回登录后的跳转路径仅允许本站应用路径。

路由、菜单和按钮使用同一权限/能力模型做交互控制，服务端对每次查询、命令、下载和持续订阅独立鉴权。用户移出项目时，API 拒绝后续读取；已有 SSE 按平台规定的权限版本通知及有界复查关闭。会话过期和项目无权访问分别展示，登录恢复后也要重新验证原资源权限。

Markdown 预览默认关闭原始 HTML；经解析和清洗的输出仍检查链接协议，外部图片默认不自动加载。HTML、SVG 和主动内容首版以转义文本或受控下载呈现；以后若开放富预览，使用独立 origin 的受限沙箱并通过外联/脚本隔离验收。禁止将目标响应直接插入控制台 DOM，也不提供以任意 URL 代替 Artifact ID 的证据代理。

证据下载走重新鉴权的 API；原始敏感数据和导出按独立权限判断。列表及普通日志使用脱敏内容，前端错误上报只带错误码、构建版本和允许的关联 ID，不上传原包、凭据或完整证据。CSP 和受控资源来源作为部署防护层，不能替代内容清洗。

## 6. 页面范围与交互规则

| 阶段 | 首批可用页面 | 明确交付的闭环 |
| --- | --- | --- |
| Phase 1 | 登录/项目选择、任务列表、任务创建、任务详情、证据详情 | 已批准范围预览 → 受控 HTTP 任务 → 状态/日志/证据 → 取消与清理；测试配置可由管理接口准备 |
| Phase 2 | 任务覆盖、Verification 详情、基础资产/Finding 证据链、报告快照 | 单 Agent 评估 → 条件和证据 → 有分母的覆盖指标 → 固定 Markdown 报告；内置场景可选 |
| Phase 3 | Agent 执行树、Worker/Intent 详情、验证交接记录 | 展示归属、等待、冲突、预算及简短决策摘要 |
| Phase 4 | 完整资产/资料页面、Finding 研判与修复、报告发布、多格式导出、配置管理 | 按角色完成版本发布、资料导入、复测及交付；未实现格式不显示可用入口 |

导航以“作业”和“配置”为顶层分组，但仅开放已实现且当前用户有权使用的能力。Phase 1 直接以任务列表为主要入口；Phase 2 的场景选择先使用内置版本，不能为了绘制配置菜单就先开发完整发布中心。

任务详情保留统一任务标识、有效范围、执行状态、清理状态和主要操作，下面按覆盖、时间线、工作区、Agent 记录组织视图；尚未实现的 Tab 不作为空壳发布。证据可按验证单元/Finding 等关联筛选，详情链接携带稳定资源 ID，服务端校验整条关系归属。

页面直接使用领域状态：任务运行状态、Verification 执行状态/verdict、Finding 证据/研判/修复/发布状态分开展示。覆盖率显示分子、分母及 CoveragePlan 版本，例如 6 evaluated / 10 纳入项；blocked、不完整验证和未执行不能显示为“通过”。零发现报告同时呈现覆盖和限制。

每个数据页面具备加载、空结果、无权限、请求失败和数据过期状态。关键动作展示实际影响和提交结果，避免所有按钮一律弹确认框；范围变更、发布等动作按业务要求展示待提交的具体内容。Task 终态后的“重新验证”建立关联新任务并重新检查授权。

## 7. 视觉、可访问性与大数据量

应用根部使用一个 ConfigProvider 管理语言、基础尺寸及主题 tokens；组件差异优先使用组件 tokens 和公开样式接口，不依赖内部 `.ant-*` DOM 结构或全局覆盖。按工作台视觉反馈，采用紧凑三栏布局，提供雾银（默认）、冰蓝、青瓷、亮石墨与原石墨主题；数字、地址和响应正文使用等宽字体。每套主题独立定义背景、文字、状态和组件 tokens，并检查实际渲染对比度。具体规则见 [视觉基线](../DESIGN.md)。

五套可切换主题已由用户确认为正式工作台的内置能力，并已提取至 `packages/theme` / `@wuji/theme`，由原型和正式 `apps/web` 共享。正式应用使用 localStorage 保存非敏感主题 ID，重新打开后恢复；有效 `theme` URL 参数可临时覆盖，用户主动选择后保存偏好并移除该覆盖。切换不重建业务状态、清空表单或发送业务命令。

状态使用文本和图标辅助，颜色不单独承担“失败/成功/阻断”的含义。表单有可访问名称、关联错误和明确必填项；抽屉/对话框管理初始焦点及关闭后的焦点恢复。键盘可完成创建、筛选、查看证据和取消，不以仅 hover 出现的操作承载关键功能。

桌面优先，同时保证窄窗口下操作和内容可读；表格可在自身容器横向滚动。组件使用稳定业务 ID，排序/筛选/分页由一处受控状态驱动，远程查询避免同时应用另一套本地过滤。

任务和证据列表采用服务端分页；日志只保存有界窗口，较早记录按游标加载。高频事件合并刷新，图谱和大文件查看器按路由/功能懒加载。初始验证夹具可包含 10,000 条任务记录，页面默认只请求 50 条；禁止一次拉取全量再在浏览器分页。

工程初始化已有构建记录，正式应用也完成了 Phase 1A/1B 对应的最小页面检查；首屏资源体积、交互耗时、长时间事件流的内存和 DOM 数量阈值仍待对应能力进入验收时确定。现有构建与最小浏览器证据不能视为性能、容量和长时间事件流已经达标。

## 8. 构建与私有化部署

Vite 生成静态 `dist`，由独立 web 容器提供文件，经 Ingress 将 `/api` 转发给 Platform API，保持浏览器同源。生产环境不使用 `vite preview` 充当应用服务器。[Vite 静态部署说明](https://vite.dev/guide/static-deploy.html)

默认部署在根路径。若交付要求子路径，必须共同配置构建资源前缀、路由 basename、API 和登录回调地址，并验证刷新及深链接；不能仅修改 Ingress 路径。SPA fallback 只处理前端页面导航，API、事件、文件和不存在的静态资源保持各自的真实响应。

公开运行配置只包含 API 相对前缀、部署显示名、构建/契约版本等非敏感项；绝不包含密钥。首版可在启动时生成 `/app-config.json`，它与入口 HTML 禁止长期缓存；带内容摘要的静态资源可长期缓存。升级保留一段时间的旧摘要资源或提供明确刷新恢复，防止已打开页面懒加载旧 chunk 失败后陷入空白。

会话、业务 API、证据和 SSE 禁止共享缓存；SSE 代理关闭响应缓冲，配置心跳及匹配的连接超时，验证重连和权限撤销窗口。前端不安装缓存业务数据的 Service Worker，不将私有报告作为公开静态资源发布。

开发环境同样通过代理访问 API，Mock 与真实 API 使用同一契约。生产构建不能携带 Mock 鉴权、测试账号或演示任务控制分支；错误监控和 source map 上传目的地需符合部署方数据策略。

## 9. 工程初始化与验证门槛

以下条目最初是正式业务开发前的一次性门槛。固定工具链、`apps/web`、共享主题、生成契约客户端、真实会话及 Phase 1B 任务主路径已按阶段落地；Phase 1A 仍为 `partial`，B2/B3 只完成最小验收。后续按受影响能力补足证据，不因每次修改重复运行全部条目。

1. 固定 Node、pnpm、React、TypeScript、Vite、antd、图标、Router、Query 和测试工具精确版本，确认 peer dependencies、浏览器基线、许可证及已知阻断问题；提交锁文件，CI 使用固定工具链和冻结安装。
2. 维护正式 AppShell、共享主题、路由和错误页；部署方式变化时验证生产构建、登录回跳、深链接刷新和按需加载，若使用子路径则纳入同一检查。
3. 从契约生成客户端，使用同一组 Schema 夹具覆盖任务状态、错误、分页和幂等命令；Schema 不兼容时明确失败，不伪造成功界面。
4. 对已实现接口使用正式平台验证同源会话、CSRF、项目切换和迟到响应；证据预览随证据 API 实现后验收，真实身份提供方的延期项按 Phase 1A 清单集中处理。
5. 在 Phase 2 页面开发前，单独完成快照/游标交接、重复/乱序事件、断线补发与权限撤销的 SSE 原型验证。

常规 CI 门槛为格式/静态检查、TypeScript 检查、生产构建、契约生成一致性检查，以及变更相关的单元和浏览器测试。Vitest 重点验证事件/状态转换、命令去重和边界处理；Playwright 验证用户实际路径、项目隔离、键盘操作和部署路由。[Vitest 文档](https://vitest.dev/guide/)、[Playwright 文档](https://playwright.dev/docs/intro)

前端 Mock 测试只能证明界面行为。权限、实际目标请求数、任务停止、预算和 Runtime 清理仍须在平台集成验收中提供执行证据；前端显示“已取消”不能代替执行端停止证明。
